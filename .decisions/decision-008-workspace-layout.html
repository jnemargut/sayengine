Workspace Layout

Information architecture 🔁 Two-way door Medium stakes

Where does everything live on screen — the 3D view, the scene list, the parameters, the AI conversation, the history? This is how the "human as creative director" idea becomes physical. A traditional layout surrounds the viewport with fixed panels; an AI-first layout might give the 3D object the whole stage and let tools appear only when needed, or make proposals the main thing on screen. The case against my pick

Floating, contextual UI is harder to build well than docked panels and easier to get wrong: cards that cover the model, inspectors that jump around, and power users who want everything pinned. Docked panels (A) are boring but battle-tested, and you could ship them in days with a panel library, spending design effort on the review experience (Decision 9) instead. Tiebreaker: if exploring many variants is the core loop rather than refining one object, the Variant Canvas (C) is the bolder, more differentiated choice — and it can be a mode inside B later.

This recommendation assumes

  • A "dock panels" toggle exists from day one, so power users can pin the scene list and inspector
  • Floating cards auto-avoid the selected object's screen bounds
  • The Variant Canvas becomes a secondary mode (Proposals tab), not the home screen
  • Proposal review style is settled separately in Decision 9 and slots into this stage
  • Tripwire: if testers spend more time moving cards than modeling, switch the default to docked panels

Where experts disagree

Pro-tool designers argue fixed panels build muscle memory and that floating UI is demo-ware. Newer creative tools increasingly put the canvas first with contextual, on-selection controls, because it lowers the barrier for non-experts. The deciding condition is the same one as Decision 7: who you're designing for first. A dock toggle lets B serve both.

Combining is fine: "Option B with C as the Proposals tab" or "Option B but docked by default"
