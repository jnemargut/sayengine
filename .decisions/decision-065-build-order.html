The case against my pick

Fire's Dying showed that tools built from a real game's pain log land better than tools built ahead, and C repeats that method exactly. A asks you to wait a week for plumbing designed before a second system tests it. If starting your game today matters more than having the new way of working from its first session, C (or B) is the better call. The tiebreaker: how much do you mind a week before your game starts?

Assumptions and tripwires

  • The core is proven on models first, since they're already in the view with steps and proposals.
  • Systems your game uses join the view inside the game's schedule, about 1–2 days each.
  • Tripwire: if the core isn't usable within about 7 working days, stop and start your game anyway (C), finishing the core from its pain log.
  • The repo slimming and backup push finish first, independent of this choice.
