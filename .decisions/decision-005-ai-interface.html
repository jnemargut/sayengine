The model gets a single tool: run a short TypeScript program against a typed modeling API inside a sandbox. Loops, conditionals and self-checks happen in one call, which is where the token savings come from — Anthropic and Cloudflare both report big wins from this pattern. But every action is opaque until the script runs, smaller/local models write worse code than they call tools, and errors surface as stack traces rather than clean validation messages.

Works well when

  • Long multi-step edits (arrays, loops, conditional fixes)
  • Token budget is a top concern

Watch out for

  • Sandbox engineering + security surface (see blender-mcp CVE)
  • Harder to show humans "what the AI is doing" step by step
  • Weaker for local/small models

The case against my pick

Two doors means two surfaces to keep working, and the MCP door mostly serves developers — the "people who never learned Blender" never open Claude Code. The strongest evidence on agent efficiency (Anthropic's code-execution post, Cloudflare Code Mode, CodeAct) points at code, not typed tools, so starting with ~20 discrete tools may leave accuracy and tokens on the table for multi-step modeling. A leaner path would be Option D from day one inside a single in-app agent, with MCP added only if users ask.

This recommendation assumes

  • Tools are grouped into modes (create / modify / inspect / propose / material), ≤ ~20 visible at a time, with tool search beyond that
  • Every tool returns structured results + validation errors the model can act on, never just "ok"
  • No arbitrary host code ever — run_script runs in QuickJS-WASM with timeout + memory cap and only produces commits
  • MCP door is primarily for development/benchmarks at first (Claude Code drives the headless engine)
  • Tripwire: if benchmark tasks average >15 tool calls or token cost per object exceeds budget, promote run_script to the default path

What the research says

  • Presenting MCP tools as a TypeScript API cut one workflow from ~150K to ~2K tokens (98.7%); needs sandboxing and limits. Anthropic: code execution with MCP
  • Tool search raised MCP-eval accuracy 49%→74% (Opus 4); programmatic tool calling cut tokens 37%; tool-use examples raised complex-parameter accuracy 72%→90%. Use tool search beyond ~10 tools. Anthropic: advanced tool use
  • Cloudflare Code Mode: MCP schemas → typed TS API, one execute tool, fresh V8 isolate per run. Cloudflare · CodeAct: up to 20% higher success, 30% fewer steps. CodeAct
  • Tool overload: RAG-MCP raised selection accuracy 13.6%→43.1% by retrieving a shortlist; practitioners report degradation past ~25–50 tools. RAG-MCP 248-tools report
  • MCP spec 2026-07-28: stateless core, versioned extensions; MCP Apps lets servers ship sandboxed UI to Claude/ChatGPT/VS Code. MCP 2026-07-28 SEP-1865 MCP Apps
  • blender-mcp (~33k stars) relies on execute_blender_code (arbitrary Python) — now CVE-2026-10688 (RCE). The anti-pattern to avoid. blender-mcp CVE-2026-10688
  • tldraw agent kit: in-app, typed schema-validated actions with auto-repair, grouped into modes; screenshot + structured shapes each turn. tldraw agent kit
  • Vercel AI SDK 6: ToolLoopAgent, per-tool needsApproval, stable MCP client — the most direct provider-agnostic TS loop. AI SDK 6
  • Zod 4 has native z.toJSONSchema(); OpenAI strict mode needs all-required keys + additionalProperties:false → normalize per provider. zod JSON Schema OpenAI structured outputs
  • Sandboxing: quickjs-emscripten works in browser + Node, exposes nothing by default; SES alone can't stop infinite loops. QuickJS comparison Hardened JS Willison survey

Where experts disagree

The "code mode" camp (Anthropic engineering, Cloudflare) says models are better programmers than tool-callers and token savings are huge. The "typed actions" camp (tldraw, Figma's MCP, most production agents) says discrete validated actions are easier to show, approve and recover from. For a creative tool where humans review every step, typed tools are the better default; code mode earns its place for long, loop-heavy edits — which is why Option C keeps both behind one registry.
