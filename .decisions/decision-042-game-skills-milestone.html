The case against my pick

Two builds at once (modules and skills) doubles the chance of tangles, and the build skill would be written against modules that are still landing, so it may need reworking in week 15. D is the more elegant answer: one milestone, a real game instead of a demo, and the skills tested on the hardest case. If you don't already have a game idea you're itching to make, D is better than inventing one for week 15.

Assumptions and tripwires

  • Assumes the skills are mostly markdown plus the game spec and build steps, so they can be built by a separate agent without touching module code.
  • Assumes you'll have a game idea ready for week 15.
  • Tripwire: if the build skill breaks twice because a module changed under it, pause it until that module's week ends.
  • Tripwire: if you don't have an idea by week 14, switch the proof to D's "tiny Raleigh game".
