The case against my pick

Option A puts eight new parts into a rough first version at once: bake, unwrap, profiles, round-trip, two engine back ends, a kit template and motion ops. When something fails in week 5, it may be hard to tell which part is to blame, and a rough kit template might teach the wrong lessons about rigging. If you'd rather each part be solid before it meets the others, B is the safe order. And if a diorama won't keep you motivated, D's finished tiny game is worth the extra weeks.

This recommendation assumes

  • Week estimates assume roughly full-time work with Claude Code, like the first build.
  • The materials, scenes, drag-to-edit and import features being built now are finished first; the diorama uses scene arrangement and material presets.
  • Each new part ships with tests and a bench task (10–14), as before.
  • Tripwire: if the character doesn't walk in Godot by the end of week 5, stop adding features and cut scope.
  • D (a tiny complete game) is the natural next milestone after A.

What the research says

  • On a benchmark of 132 Godot tasks, the best AI agent passed 54%, doing worst on 3D graphics and animation. A milestone that has Claude run, screenshot and play-test early tests exactly that weak spot. GameDevBench
  • The first build's thin slice found about a dozen real bugs in a week of self-benchmarking, including the collapsed roof and invisible openings, all caught because the whole loop ran end to end. bench/TASKS.md
  • Solo developers most often fail by building infrastructure instead of a game. A milestone that ends in something playable guards against that. Game Developer
