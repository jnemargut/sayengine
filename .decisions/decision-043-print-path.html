Decision 43 of 46 · Printing path

The Path From Model to Print

Interaction 🚪 One-way door High stakes

You'll occasionally make something to print on your A1 mini (no AMS, single colour) with Bambu Studio 2.08 on this Mac. Today the studio can export an STL, and the rest is up to you. Bambu Studio has a real command line (orient, arrange, presets, filament, build the project file), and since January 2025 starting a print from outside Bambu's own apps needs either Bambu Connect (you still confirm) or an unsupported developer mode. This picks where the studio stops and you take over.

The case against my pick

A leans on Bambu Studio's command line, which has an open bug where headless runs crash on Apple Silicon when presets inherit from others; merging the presets ourselves should avoid it, but a Bambu Studio update could change the preset files and quietly break the step. For an occasional printer, D has zero moving parts: if A breaks the one time a year you need it, D would have just worked. A should fall back to D automatically when the command line fails.

Assumptions and tripwires

  • Assumes your A1 mini 0.4 nozzle and a PLA preset (your "Bambu PLA Basic @BBL A1M" copy) are the defaults, with filament selectable by name.
  • Assumes the merged-preset trick avoids the Apple Silicon crash; checked with a test print file on install.
  • Falls back to D (plain STL plus open -a BambuStudio) whenever the command line fails, saying why.
  • Tripwire: if a Bambu Studio update breaks the command line twice, make D the default.
