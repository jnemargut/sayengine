Structured Diagnostics Only

The model receives
"commit": "c42", "op": "set_param legRadius 0.015", "bbox": [0.45, 0.85, 0.48], "units": "m", "manifold": true, "triangles": 8412, "parts": { "leg_bl": { "touches": ["seat"], "minY": 0.004 }, "leg_br": { "touches": ["seat"], "minY": 0.000 } }, "checks": [ { "FAIL": "leg_bl not grounded (4 mm gap)" }, { "PASS": "no self-intersections" }, { "PASS": "seat height 0.45 ± 0.01" } ]
Exact and cheap (~300 tokens) — but says nothing about whether it looks like a good chair
After every change, the engine returns hard numbers: dimensions, watertightness, which parts touch, collision checks, and pass/fail rules ("legs must touch the floor"). Precise, cheap, and immune to the vision mistakes models make. But it's blind to everything aesthetic — proportions, style, "this looks like a stool, not a chair" — which is half of what users will ask for.

Works well when

  • Catching geometric errors with certainty
  • Cheap enough to run after every single step

Watch out for

  • Can't judge style, proportion, "Craftsman-ness"
  • Only finds problems you wrote rules for

After every change, render front/side/top/three-quarter views and hand them to a vision-capable model. It can judge style and proportion like a human glancing at the screen, and it's what most "AI + Blender" demos do. But benchmarks show vision models are close to guessing on exactly what modeling needs most: whether two parts touch, overlap, or are the right size. They'll confidently approve a floating leg.

Works well when

  • Judging overall look, style, silhouette
  • Matching against a reference image

Watch out for

  • Unreliable on touching/overlap/metric distances
  • ~1,400 tokens per 1024² view on Claude → ~5.6K per check
  • Image-only feedback lowered CAD compile rates in one study

Checks + Labeled Views

1 · Deterministic checks (authority)
"checks": [ { "FAIL": "[3] leg_bl not grounded (4 mm)" }, { "PASS": "manifold · no intersections" } ], "parts": { "1":"seat", "2":"back", "3":"leg_bl", "4":"leg_br" }
2 · Labeled views, sent as separate images (advice)
front · labeled
iso · labeled
Same IDs in JSON and image; failing part highlighted. Pictures answer only "does it look right?"
Every change returns both, with clear roles. The engine's checks are the authority on anything measurable: dimensions, touching, collisions, watertightness. Then 2–4 views, sent as separate images (combined grids measurably confuse models), with numbered labels matching the part IDs in the JSON and failing parts highlighted in red. The model uses pictures only for questions numbers can't answer: proportion, style, "does this read as a chair?"

Works well when

  • You want both correctness and taste
  • The model can reference "part 3" across text and image
  • Matches every working system found (CADCodeVerify, SceneCraft, Zoo, tldraw)

Watch out for

  • ~3–6K tokens per full check — run images at milestones, not every step
  • Needs headless rendering in Node (persistent Playwright page)
  • Label overlays need careful placement to stay readable

A different model family judges the builder's work against the request
A second AI — ideally from a different model family — looks at the renders and the original request (or a reference image) and returns a scored critique, like an art director. Research systems like LL3M and BlenderAlchemy use this. It catches "this isn't what I asked for" better than self-review. But critics agree with humans only ~66% of the time at best, prefer outputs that resemble their own style, sometimes just pick whichever candidate came second, and add a full extra model call per round.

Works well when

  • Style matching against a reference image
  • Choosing between variants

Watch out for

  • Self-preference + position bias in judges
  • Doubles cost and latency per iteration
  • Still can't measure — needs checks underneath anyway

The case against my pick

The measured gain from adding visual feedback is modest — CADCodeVerify improved geometric accuracy ~18% over no feedback, and a solver with ground-truth geometry beat it outright — so images might cost 5–10× the tokens of the JSON for a small win. Reliable headless rendering in Node is fiddly (SwiftShader screenshots took ~24 s in one report), and the label-overlay pipeline is real work in week 5. A leaner start is Option A only, adding images when the first benchmark shows a failure that numbers can't catch.

This recommendation assumes

  • Checks run after every commit; images only at milestones (end of a plan step, before proposing to the human) or when the model asks via an inspect_visual tool
  • Rendering happens in the already-running browser view or one persistent Playwright page — never a fresh browser per frame
  • Rules ("legs grounded", "no intersections", "seat height in range") live with the object's semantic type and grow from benchmark failures
  • Option D's critic arrives later as an optional step: different model family, fixed questions, shuffled order, only after checks pass
  • Tripwire: if visual checks change the outcome in fewer than 10% of benchmark runs after 2 weeks, drop images to on-demand only

What the research says

  • CADCodeVerify: 4 rendered views + self-generated validation questions improved geometric accuracy ~18% over no feedback and ~7% over image-only feedback; a ground-truth geometric solver did best. Gains stop after 2 refinement rounds. CADCodeVerify
  • 3D-Premise (image-only feedback) dropped compile rate 96%→91%; spatial reasoning named as the main failure. 3D-Premise
  • "VLMs are blind": frontier models averaged ~56–58% on "do these two circles overlap/touch?" — touching/intersection must be computed, not seen. VLMs are blind
  • MindCube: VLMs near random building a scene model from few views (37.8%); giving them a structured map first raised it to 60.8%. MindCube · SpatialRGPT: metric distances need depth/region grounding. SpatialRGPT
  • Stitching views into a 2×2 grid made most models worse — send separate images. multi-image study · Set-of-Mark numbered labels let models reference regions reliably. Set-of-Mark
  • BlenderGym: best VLM verifier agrees with humans ≤0.66 (humans 0.79); some verifiers pick by position. BlenderGym · LLM judges prefer their own outputs. self-preference study
  • Self-correction without external ground truth can make results worse. Huang et al.
  • Production patterns: Zoo's agent uses four-view snapshots + engine geometry queries; tldraw sends a screenshot + structured shape list each turn; SceneCraft pairs numeric constraints with visual review. Zookeeper tldraw AI docs SceneCraft
  • Claude image cost ≈ width×height/750 tokens (~1,400 per 1024² view). Claude vision docs
  • Headless three.js: SwiftShader via Chromium works but is slow (~24 s → ~6 s with llvmpipe in one report) — keep a persistent page. WebGL without a GPU

Where experts disagree

Agent-demo builders lean on screenshots because they're general and impressive; CAD researchers lean on geometric checks because they're right. GPTEval3D found GPT-4V's pairwise judgments of 3D assets align well with humans — for ranking overall quality, not verifying exact geometry. The split resolves by job: images for "which looks better", numbers for "is it correct".
